- **영향:** 없음. 옮긴 뒤 원위치로 되돌렸습니다.

## ADR-003 (2026-11-08, 채택) 선물 bookTicker는 REST 1초 폴링으로 수집
- **맥락:** Phase 0 실측 결과는 다음과 같습니다(`docs/measurements/phase0.md` 1·2절).
  - WS 상위 20심볼: 초당 1,550 메시지, 원본 하루 27GB(추정), 코어 약 0.5개 상시 사용
  - REST 전 심볼(804개) 1회: 121KB, 30회 CPU 0.3초(코어 약 1%), weight 여유 큼, 응답에 이벤트 `time` 포함
- **선택지**
  - (a) WS 원본을 받아 초 경계로 샘플링
  - (b) REST로 1초마다 전 심볼을 받아 상위 K만 저장
- **결정:** (b)
- **근거:**
  - 노트북의 발열과 CPU 부담을 크게 줄입니다(SSD 과열 이력).
  - 전 심볼을 관측할 수 있습니다.
  - `time` 필드를 `event_time`으로 쓸 수 있습니다.
- **대가**
  - 샘플 시점에 네트워크 지터(RTT 약 40ms)가 섞입니다. `received_at`과 `time`을 함께 저장합니다.
  - 수신량이 하루 약 10GB입니다. 가정용 회선이라 문제없다고 판단하지만 **미확인**입니다.
  - 초 내부의 미시구조 정보는 잃습니다. 분~일 시간축에는 충분합니다.
- **재검토 조건:** 초 단위 미시구조 가설이 생기면 해당 심볼만 WS로 수집합니다.

## ADR-005 (2026-11-08, 채택) 시계 기준과 벌크 metrics의 시각 해석
- **시계 기준:** Binance `/api/v3/time`을 씁니다(실측 offset −16ms, RTT 42ms). Upbit은 `Date` 헤더 해상도가 1초라 기준으로 쓰지 않습니다.
- **metrics `create_time`:** 공식 정의가 없어 구간 시작인지 끝인지 미확인입니다. **구간 시작으로 보수적으로 가정**합니다(가용 시각 = `create_time` + 5분 + lag). 근거는 설계 v2.1 §5.4입니다. dev-tools Gotchas에 따르면 Dependabot이 이 workflow를 갱신하지 못할 수 있으므로, 수동으로 확인합니다.
