# Phase 4 대규모 탐색 계획 (설계 기준: v2.1 §8, §13 4행) — 초안, 승인 전 구현 금지

## 목표와 완료 기준 (§13 4행)
- 목표: S0~S3 단계 파이프라인, N_eff(ONC), 계열별 Thompson Sampling, MAP-Elites.
- 완료 기준(객관적)
  - **비용 예측 ±50%:** 단계별 `cost_s` 예측 대비 실측 비율이 0.5~1.5 안에 들어야 합니다(배치 단위 90% 이상).
  - **회계 누락 0:** 적합도 평가 1회마다 trial 1건이 기록돼야 합니다. Optuna 내부, 특징 선택, 민감도 분석, 중단된 실행도 모두 포함합니다.
- 비목표
  - 전략 채택, validator, 봉인 홀드아웃 사용, StepM은 Phase 5입니다.
  - GA, 6번째 이후 계열은 다루지 않습니다.
  - 실거래는 하지 않습니다.
  - 이 Phase의 어떤 결과도 성과 증거로 보고하지 않습니다.

## 현재 상태 (실측, 2026-11-10 research.db 읽기 전용 조회)
- 시도: S2 done 46건(평균 `cost_s` 1.34초, 최대 1.49), S3 done 31건(평균 0.49초), smoke 20건. 중복 0입니다.
- `feature_eval` 테이블은 있지만 0행입니다. S1 IC 표는 미구현입니다.
- `backtest_run.pnl_daily`(zlib float64, 일간)가 S2 이상 시도마다 저장돼 있습니다. N_eff 입력으로 쓸 수 있습니다.
- `trial.stage`는 S0~S3를 이미 허용합니다. `cost_s`도 기록 중입니다.
- 패널 1회 적재는 3.7~4.9초, 최대 private 메모리는 763~827MB입니다(8심볼, 6개월, 1h).
- 정책은 Phase 3 TS(계열 단위, 가짜 보상) 하나뿐입니다. 비용 정규화와 할인은 없습니다.

## 27점 고정 격자의 한계 분석
`strategy/templates.py`의 GRID는 trend 6, mean_reversion 6, momentum 6, funding_basis 4, volatility 5로 **합계 27점**입니다. Phase 3 시험용으로 사전 등록한 격자이며, 탐색 공간으로 보면 다음 한계가 있습니다.
1. **소진이 빠릅니다.** 계열당 4~6점이라 몇 사이클이면 모두 소진됩니다. Phase 3 실측에서 이미 `exhausted` 판정이 나왔습니다. 이후 TS는 고를 대상이 없어 PAUSED로 갑니다.
2. **해상도가 거칩니다.** 파라미터마다 2~3개 값만 있고 서로 독립적이지 않습니다. 예를 들어 trend의 fast/slow는 직교 격자가 아닙니다. 그래서 국소 최적을 찾거나 민감도(평탄성)를 판단할 수 없습니다.
3. **구조 축이 고정돼 있습니다.** 신호 연산, 진입 규칙, 사이징, 유니버스 크기, 시간틀이 템플릿에 박혀 있습니다. 다양성은 사실상 5개 계열 수준입니다. MAP-Elites의 행동 기술자(회전율, 보유기간, 노출)가 거의 변하지 않습니다.
4. **N_eff가 무의미합니다.** 27개는 거의 상관된 소수 군집이라 ONC 결과가 2~5개 군집에 그칩니다. DSR의 V[SR] 추정 분산도 큽니다.
5. **TS 학습 신호가 부족합니다.** 팔(계열)당 표본이 4~6개라 사후분포가 사전분포를 크게 벗어나지 못합니다.
6. **S1 대리 지표가 없습니다.** 모든 점이 바로 S2(1.3초)로 가므로, 공간을 넓히면 비용이 선형으로 늘어납니다.
7. **장점:** 사전 등록이라 다중성 회계는 명확합니다. Phase 4에서는 이 성질을 "문법 공간 + 사전 등록한 탐색 규칙"으로 옮겨야 합니다(공간 크기를 문법으로 계산해 보고).

결론: 격자를 넓히지 말고 **파라미터는 연속·정수 범위 + 구조 축은 DSL 문법**으로 바꿉니다. 그리고 S1에서 대부분을 걸러 S2 예산을 지킵니다.

## 순서와 단계별 검증 기준
- [ ] 1. **공간 정의와 계산.**
  - `strategy/space.py`: 계열별 파라미터 범위(정수/연속, 사전 등록)와 구조 축(신호 변환, 진입 규칙, 사이징 창, 유니버스 n)을 정의합니다.
  - 이론적 공간 크기를 문법으로 계산합니다.
  - 생성기는 시드 고정 시 결정적이어야 합니다.
  - 검증
    - 생성된 spec이 100% S0를 통과하거나, 이유가 기록된 채 거부됩니다.
    - 같은 시드면 같은 결과가 나옵니다.
    - 공간 크기 계산이 손으로 센 작은 사례와 일치합니다.
- [ ] 2. **S0 정적 검사 단계화.**
  - 기존 `strategy/s0.py`를 파이프라인 단계로 연결합니다.
  - 정규형 해시로 중복을 제거하고, 지표 계층(생성 수, 중복 제거 후 수)을 기록합니다.
  - 검증: 중복이나 거부도 trial(stage S0)로 1건씩 기록됩니다. 회계 불변식 테스트를 통과해야 합니다.
- [ ] 3. **S1 IC 표(ADR-022 조건부 승인 정의 그대로).**
  - 라벨: `decision_time + latency` 이후 다음 봉 시가 기준 h봉 수익률입니다. 비용·펀딩 포함판을 따로 둡니다.
  - IC: 횡단면 Spearman을 씁니다. 유의성은 HAC(Newey-West) t, 또는 겹치지 않는 표본으로 구합니다.
  - 결과는 `feature_eval`에 기록합니다.
  - 계열별 대리 지표를 둡니다(이벤트형은 이벤트 조건 수익률).
  - 검증
    - 합성 데이터에서 알려진 IC를 재현합니다(±0.02).
    - 미래 정보 주입 시 IC가 0 근처로 떨어지는 누수 테스트를 통과합니다.
    - HAC t가 statsmodels 없이 기준식과 일치합니다(작은 고정 사례).
    - 평가 1회당 trial 1건이 기록됩니다.
- [ ] 4. **비용 모델 `cost_s ≈ a + b·rows·ops`와 피크 메모리 모델.**
  - 단계별 실측(S1, S2, S3)으로 최소제곱 적합을 합니다.
  - 배치 시작 전에 예측하고, 예산을 넘으면 표본(심볼, 기간)을 줄입니다.
  - 검증
    - 보류 배치의 90% 이상에서 예측/실측이 0.5~1.5 안에 듭니다(완료 기준).
    - 메모리 예측을 넘으면 실행 전에 거부합니다.
- [ ] 5. **충실도 편향 관리.**
  - S1 탈락 후보의 **5%를 무작위로 승격**합니다(시드 기록). 계열별로 S1 대 S3 순위상관을 기록합니다.
  - 검증
    - 승격 비율이 5% ± 이항 95% 구간 안에 듭니다.
    - 승격된 시도에 `promoted_random` 표시가 있고 회계에 포함됩니다.
- [ ] 6. **탐색기: Random 기준선과 TPE.**
  - Optuna 사용 여부를 확인받습니다. 승인되면 버전을 고정하고, 내부 평가마다 trial을 기록합니다.
  - Random 대 TPE를 같은 `cost_s` 예산으로 비교합니다. 지표는 회수율, FWER, N_eff 증가량입니다.
  - 검증
    - Optuna 내부 평가 수와 trial 수가 정확히 같습니다.
    - 심어 둔 신호(합성)의 회수율을 두 방법 모두 보고합니다.
- [ ] 7. **N_eff (ONC 하나만).**
  - S2 이상 `pnl_daily` 상관 행렬 → ONC 군집 → N_eff를 구합니다.
  - DSR은 두 번 보고합니다: N_eff 기준과 N_total(S1 포함) 기준. 판단에는 보수적인 쪽을 씁니다.
  - `min_sr(N_eff, T_split, q, skew, kurt, ρ)`와 참조 표를 둡니다. SE는 Mertens 식으로 구합니다.
  - 검증
    - 블록 구조 합성 상관에서 군집 수를 정확히 복원합니다.
    - MC로 E[max]와 95% 분위를 ±1% 안에서 재현합니다(§8 단위 테스트).
    - 단위는 기간 단위로 통일하고, 연환산을 섞지 않았는지 테스트합니다.
- [ ] 8. **계열별 Thompson Sampling(할인·비용 정규화).**
  - 보상은 선별 구간 안의 별도 검증 분할 성과(DSR 보정)를 실측 `cost_s`로 나눈 값입니다. 표본 내 통과율은 쓰지 않습니다.
  - 할인 또는 슬라이딩 창을 쓰고, 사전분포를 명시합니다(초기 사전분포는 기록하고 실측으로 재조정).
  - 계열별 최소 예산을 둡니다.
  - 검증
    - 고정 보상 시뮬레이션에서 최적 팔 선택 비율이 수렴합니다.
    - 비정상(보상 전환) 시나리오에서 할인 TS가 비할인보다 빨리 적응합니다.
    - 비용이 2배인 팔은 보상이 절반으로 반영됩니다.
- [ ] 9. **MAP-Elites 아카이브.**
  - 행동 기술자는 회전율, 평균 보유기간, 순노출 같은 사전 등록 축입니다(성과로 고른 축은 쓰지 않습니다).
  - elite에 수축 추정을 적용하고, 신호 상관 상한을 둡니다.
  - 검증
    - 아카이브 채움률과 다양성을 기록합니다.
    - 같은 셀 교체 규칙이 결정적입니다.
    - 수축 후 순위가 표본 수에 따라 올바른 방향으로 바뀝니다(합성).
- [ ] 10. **Director 통합과 실측 실행.**
  - Director는 계열과 구조를 고르고, 숫자는 탐색기가 정합니다(§7).
  - 실데이터 소규모 배치(예: 계열당 200 S1 → 상위 + 5% → S2 → S3)로 비용 예측과 회계 완료 기준을 측정합니다.
  - 수집기 우선순위를 보장합니다.
    - 연구 작업자는 BelowNormal 우선순위, 스레드 상한, 동시 1개로 시작합니다(작업자 2개는 실측 후).
    - 벌크 다운로드나 수집기 하트비트에 지연이 생기면 중단합니다.
  - 검증
    - 완료 기준 2개를 측정표로 보고합니다.
    - 수집기 gap과 하트비트가 실행 전후로 같습니다.
- [ ] 11. **문서.** progress, ADR(공간, S1, TS, ONC, MAP-Elites), failures, operations, test-results, measurements를 갱신합니다.

## 위험
- **다중성 폭증:** S1 시도 수가 수만 건이 될 수 있습니다. 그래서 N_total 기준 DSR을 함께 보고하고, 시도 회계를 빠짐없이 합니다.
- **S1 편향:** IC가 높은 계열로 쏠릴 수 있습니다. 5% 무작위 승격과 순위상관으로 측정합니다.
- **자원:** RAM 16GB에서 수집기와 벌크가 함께 돕니다. 동시 작업자 1개로 시작하고, 메모리 예측으로 거부합니다.
- **비용 모델 미보정(ADR-021):** 모든 S2/S3 수치는 "보정 전"으로 표시합니다.
- **데이터 범위:** 현재 8심볼, 6개월입니다. T_split이 짧으면 `min_sr`가 높아집니다(검정력이 낮다는 사실을 그대로 보고).
- **LLM 사용:** 탐색 자체는 LLM 없이 돌아갑니다. Director LLM은 구독 CLI 경로만 쓰고, 사용량 한도에 걸리면 PAUSED입니다.
