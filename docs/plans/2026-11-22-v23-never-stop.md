# v2.3: 멈추지 않는 자율 캠페인 (라운드 연속·데이터 큐 소비·검정력 확대·예약 실행)

## 목표
캠페인이 셀을 다 쓰면 "exhausted"로 끝나지 않고 다음 라운드로 넘어가게 한다. 다음 라운드는 데이터 큐 소비 → 새 데이터가 들어온 셀 재개방 → 사전 등록 격자 확장 순으로 만든다. 사용자가 등록한 예약 작업에서 무인으로, 몇 주 단위로 돌게 한다. 통계 기준은 그대로 두고, 확인 구간 결합과 새 데이터·계열로 검정력을 높인다. v22-rebuild의 남은 단계(A5·A7·B4·B10·B12)를 흡수한다.
비목표: 판정 규칙(ADR-042)·α/k·봉인 창 변경, 실거래, 유료 데이터·API, lake 상한(200GB) 상향, LLM Director를 캠페인 루프의 주 구동기로 쓰는 것.

## 가정
- 사전 등록 격자(v2.2 §5·ADR-047): timeframe {1h,4h,1d} × top-M {30,100} × 창 {w1,w2} × 계열 11(+데이터가 생기면 보류 계열). 라운드가 넘어가도 이 격자 밖으로 축을 새로 만들지 않는다. 새 축은 ADR로 먼저 등록한다.
- 한 라운드 안의 셀 은퇴 규칙(max_pulls 3 등)은 유지한다. 다음 라운드는 "새 데이터가 생긴 셀"과 "아직 안 돈 격자 셀"만 연다. 같은 셀·같은 데이터 버전을 다시 여는 일은 없다(중복 평가 0). 같은 셀이라도 데이터 버전이 바뀌면 새 trial로 센다(N_total 포함).
- S3 귀무 기준의 N은 라운드를 넘어 누적한다(기준 완화 없음).
- 다운로드는 하루 수 GB 규모다. 1파일씩 받고, 파일럿 투영이 lake 상한 200GB를 넘는 tier는 건너뛰고 사용자 결정으로 남긴다.
- 메모리: 1h top-100 패널 적재가 약 1.6GB다(research gate 2GB). 그래서 캠페인과 다운로드는 동시에 돌 수 있게 하되 연구 프로세스는 하나다(`run/research.lock`).

## 선택한 접근
**A. 기존 캠페인 핵심에 "라운드"를 더한다(채택).** 순수 핵심 `search/campaign.py`에 `next_round(state, available, grid)`를 둔다. 이 함수는 다음 둘 중 하나를 돌려준다. (1) 재개방·확장할 셀 목록. (2) `waiting_data`(받을 데이터만 남음). 러너 상태에는 `exhausted` 대신 `waiting_data`를 둔다. 데이터 큐는 별도 도구가 소비한다(I/O는 얇은 어댑터). 예약 작업 두 개(캠페인 틱, 데이터 큐 틱)가 서로 상태 파일로만 만난다.
- 결정 이유: 이미 테스트된 순수 핵심·재개·회계 불변식을 그대로 쓴다. 변경이 작고 I/O 경계가 유지된다.
- B. LLM Director가 루프 전체를 구동: 구독 CLI 한도와 비용 때문에 무인 장기 실행이 불안정하고, 가설 공간이 사전 등록 격자 밖으로 나가 다중성 회계가 흐려진다. 기각.
- C. 외부 스크립트가 c3, c4…를 더 큰 격자로 재시작: 재개방 규칙이 없어 같은 셀을 반복하고, 실행 간 S3 귀무 N 누적이 끊긴다. 기각.

- **다중성 부풀림:** 라운드가 늘수록 trial이 늘어난다. N_total·S3 귀무 N은 누적하고, 결합 확인도 판정마다 N에 넣는다. 기준은 낮추지 않는다. 결과가 계속 0이면 그것이 산출물이다(셀별 "검정력 P로 연 SR ≥ X 배제").
- **holdout 누수:** 새 데이터셋은 seal_window 등록 전에 연구가 읽지 못하게 한다(B4 bootstrap 경로 재사용, 7단계 테스트).
- **메모리·열:** 연구 프로세스는 하나, 패널도 한 번에 하나만 올린다. research gate 2GB, `POLARS_MAX_THREADS=2`, 다운로드는 1파일씩 BelowNormal로 돌린다.
- **디스크:** tier 투영이 상한을 넘으면 그 tier만 건너뛰고 사용자 결정으로 남긴다.
- **상태 파일 호환:** c1 JSON은 그대로 읽힌다(2단계 테스트). c2는 새 run id로 시작한다. 되돌리기: 예약 작업 `Disable-ScheduledTask`, `run/STOP-campaign`, 코드 revert. 데이터는 추가만 하므로 catalog 행은 지우지 않는다.
- **알파가 실제로 없을 수 있음:** 수익은 보장되지 않는다. 산출물은 통과 후보 또는 음성 결과다.
