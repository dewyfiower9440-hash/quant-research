**사용자 결정 (2026-11-08)**

## 진행 원칙
- 단계마다 다음 순서로 진행합니다: 설계 확인 → 테스트 먼저 → 구현 → 선언 게이트 → 실패 분석·수정·회귀 → 문서 갱신 → 커밋 → push → CI 확인.
- **DONE 기준:** 완료 조건과 관련 테스트를 모두 통과해야 합니다.
- **같은 방식이 두 번 실패하면 BLOCKED로 둡니다.** 증거와 시도 이력을 `docs/failures.md`에 남기고, 서브에이전트로 원인을 독립적으로 분석합니다. 의존 작업은 멈추고 사용자에게 보고합니다.
- 테스트를 삭제하거나 기준을 완화하지 않고, 임시 우회책을 최종 해결로 처리하지 않습니다.
- **문서:** `docs/progress.md`, `docs/decisions.md`, `docs/failures.md`, `docs/test-results.md`, `docs/measurements/phase0.md`(설계 기준서 §19). 단계마다 갱신합니다.
- **자원 한도**
  - 수집 프로세스는 RAM 300MB 이하입니다.
  - Polars·Numba·DuckDB 스레드 상한을 설정합니다.
  - 벌크 다운로드는 SSD 온도와 디스크 상한(기본 200GB, 80% 경보)을 지킵니다.

  - 문서 5종의 골격을 만듭니다.
  - GitHub private 저장소를 만들고 push한 뒤 CI를 확인합니다.
  - **완료 조건:** 게이트 통과, CI 성공(run id 기록).
- [ ] 2. **Phase 0 측정** → `docs/measurements/phase0.md`. 이 단계의 측정 스크립트도 테스트 대상입니다.
  - 측정 항목
    - Binance 현물 WS, 선물 `/public`·`/market` WS, Upbit WS의 접속 여부와 30초 메시지율
    - bookTicker(상위 20)의 CPU와 메시지율
    - Binance·Upbit 서버 시각과의 offset, RTT
    - `metrics`·`bookDepth` 샘플 파일 1개씩의 컬럼과 타임스탬프가 구간 시작인지 끝인지
    - Upbit 분봉 최대 과거 범위(이진 탐색 소수 요청)와 `ask_bid` 매핑
    - 1일치 예상 저장 크기(1시간 실측 × 24)
    - Polars·DuckDB·Numba 마이크로벤치마크
    - 여유 RAM과 디스크
  - SSD SMART 온도는 관리자 권한이 필요합니다. 승인받지 않았으므로 "미측정"으로 기록하고 사용자에게 요청합니다.
  - **완료 조건:** 측정표와 결정(bookTicker를 WS로 받을지 REST 1초로 받을지)이 `decisions.md`에 기록됨.
- [ ] 3. **원본 캡처기 최소판 (T0 즉시 가동).**
  - 기능
    - JSONL 1시간 세그먼트. 줄마다 `received_at`, 서버 시각 보정 offset, collector 버전과 git SHA를 기록합니다.
    - fsync는 1~5초 또는 N줄마다, 세그먼트를 닫을 때도 실행합니다.
    - 시작할 때 잘린 꼬리를 격리하고, 그 구간을 gap으로 자동 등록합니다.
    - 단일 인스턴스 잠금, 하트비트, `supervisor`(백오프 재시작)
  - 수집 대상
    - Binance: forceOrder, markPrice, bookTicker 1초 샘플(2단계 결정에 따름), OI·비율·basis 30일 재수집 루프, exchangeInfo·24hr·서버 시각
    - Upbit: 체결 cursor 따라잡기, 호가 1초 샘플, 마켓·경보 스냅샷, 공지
  - 레이트 리밋: Binance는 weight 헤더와 런타임 rateLimits, 429·418·451 처리. Upbit는 `Remaining-Req` 헤더, 429·418 처리, 경로 끝 `/` 금지.
  - **완료 조건**
    - 기록한 응답(fixture)으로 파서와 레이트 리미터 테스트 통과
    - 강제 종료 후 꼬리 격리와 gap 등록 테스트
    - 2중 실행 차단 테스트
    - 실제로 1시간 연속 수집하고 결과 확인
- [ ] 4. **조기 백업과 복원 리허설.**
  - robocopy로 같은 SSD의 별도 폴더에 일간 복사합니다. 외부 대상은 미정이며, 결정되면 경로만 바꿉니다.
  - 원본 JSONL과 SQLite(`VACUUM INTO`)를 포함합니다.
  - 복원 리허설을 1회 합니다.
  - **완료 조건:** 복원 후 sha256과 행 수 100% 일치. 외부 백업이 없으므로 상태는 "부분 완료".
- [ ] 5. **카탈로그 스키마.**
  - 테이블: `instrument`(계보), `dataset`, `gap`(`no_trade` 구분), `seal_policy`(epoch 포함, T0 비율은 지금 확정), `universe_membership`, `lag_policy`(단조 증가만 허용)
  - 마이그레이션은 번호 SQL과 `user_version`으로 관리합니다.
  - **완료 조건:** 마이그레이션 테스트, lag 정책 하향 변경 거부 테스트.
- [ ] 6. **`as_of`·`join_asof` API.**
  - 구간 데이터의 시각은 구간 종료로 정규화합니다.
  - 버전이 붙은 lag 정책을 적용하고, 봉인 경계를 강제합니다.
  - 직접 읽기 금지 아키텍처 테스트와 누수 테스트(미래 값 주입, 구간 시작 타임스탬프 주입)를 둡니다.
  - **완료 조건:** 위 테스트 통과.
- [ ] 7. **컴팩션과 정규화.**
  - 원본 → Parquet로 바꿉니다. 파일은 불변이고 새 이름으로 쓴 뒤 catalog 포인터만 교체합니다.
  - 재수집에서 값이 바뀐 행은 버전으로 추가합니다(바이템포럴).
  - 기록한 원본으로 재생 테스트를 합니다.
  - **완료 조건:** 재생 결과가 결정적이고, 리더가 파일을 연 상태에서 컴팩션해도 성공하며, 재수정 시 두 버전이 모두 조회됨.
- [ ] 8. **Binance 벌크 T1.**
  - 시점별 top-K 합집합 유니버스로 대상 심볼을 정합니다.
  - `.CHECKSUM` 검증, µs/ms 판별, prefix 단위 증분 재생성 감지, zip은 검증 후 삭제하고 manifest만 남깁니다.
  - SSD와 디스크 상한을 지킵니다.
  - **완료 조건:** 체크섬 100%, 대조 샘플이 REST와 일치.
- [ ] 9. **Upbit 분봉 백필.**
  - candle 그룹은 초당 10회/IP 한도를 백필과 실시간이 함께 씁니다.
  - 봉이 없으면 `no_trade`로 기록합니다.
  - **완료 조건:** fixture 테스트, 샘플 구간 대조.
- [ ] 10. **모니터.**
  - 디스크, RAM, 시계 offset, gap, 하트비트를 감시하고 incident를 기록합니다. 경보는 로그온 세션에 표시합니다.
  - 작업 스케줄러에 supervisor를 등록합니다(부팅 시 실행, 이미 실행 중이면 새로 시작 안 함). **사용자 계정 작업으로, 관리자 권한은 쓰지 않습니다.**
  - **완료 조건:** 강제 종료 후 복구 테스트, 재부팅 후 5분 안에 복구(사용자가 재부팅할 때 확인).
- [ ] 11. **7일 연속 운영 검증 (validate, 세션 밖).**
