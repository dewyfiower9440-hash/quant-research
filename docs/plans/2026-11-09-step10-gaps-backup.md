- **`data/gapscan.py`**
  - 대상: 1초 주기 소스(`binance.um.book_ticker_1s`, `upbit.orderbook_l1_1s`)의 닫힌 세그먼트
  - 각 세그먼트를 스트리밍으로 읽어 recv 간격이 임계값(30초)을 넘는 구간을 gap으로 기록합니다.
    - cause `unknown`, detail `receive_gap`
    - 실제 원인은 절전, 네트워크, 정지 중 무엇인지 알 수 없습니다.
  - 세그먼트 경계를 넘는 공백은 `gapscan_segment`(마이그레이션 0005)에 저장한 직전 세그먼트의 마지막 recv와 비교해 잡습니다.
  - 처리 방식
    - 증분·멱등으로 동작합니다(스캔한 세그먼트는 건너뜀, gap은 `insert or ignore`).
    - 첫 실행 때 기존 세그먼트 전체를 스캔합니다(소급 기록).
- **실행 위치:** rest 작업 프로세스의 컴팩션 자식 프로세스에서 컴팩션 직후 실행합니다. 수집기 메모리에 영향이 없습니다.
- **강제청산 WS:** 이벤트성이라 수신 간격만으로 공백을 판단할 수 없습니다. 같은 시간대의 1초 소스 공백으로 판단합니다(한계로 기록).
- **백업:** 파일 단위로 `FileNotFoundError`를 건너뜁니다(`vanished` 집계). 다음 실행에서 `.gz`가 복사됩니다.
- **절전 방지(OS 전원 설정):** 사용자 지시("다른 OS 설정 변경 금지")에 따라 변경하지 않습니다. 위험과 방법은 운영 문서에 기록합니다.
