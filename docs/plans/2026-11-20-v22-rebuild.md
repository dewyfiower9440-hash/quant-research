## Context (실측, 2026-11-20)
- **데이터는 이미 있는데 3%만 썼다.** lake에 Binance USDⓈ-M 1분봉·mark·index·premium **632심볼, 2020-01~2026-10**(약 61GB, `bulk_file` 10,347~10,487파일). 그중 48심볼은 48개월 이상, 21심볼은 72개월 이상. 연구(`backtest_run` 734건)가 읽은 창은 **2025-01-01~2025-07-01, 8심볼뿐**(웜업 30일 포함 시 2024-12-02부터). **2020-01~2024-11은 연구가 한 번도 읽지 않았다.**
- funding·metrics(5m)·bookDepth·spot klines는 파일럿 2심볼 1개월씩만 있다(`tools/bulk_extras.py`가 전체 유니버스를 지원하지만 미실행). 디스크 여유 246GB, lake 상한 200GB 중 63GB 사용.
- 봉인: 벌크 데이터셋 epoch 1 = 연구 < 2026-07-01, holdout [2026-07-01, 2026-11-01)(4개월, ADR-013). 판정 규칙 α/k = 0.05/20(ADR-022). **실제 holdout 질의 0건**(validator.db 미생성) → 규칙·봉인 재등록이 엿보기 없이 가능한 마지막 시점이다.
- 4개월 holdout에서 α/k 통과에 필요한 연 SR ≈ 4.9, 1년 2.8, 23개월 2.0(root-cause §2). 현재 holdout 길이로는 진짜 연 SR 2 전략도 통과 불가.
- 귀무 거짓양성: 희소 pnl(비영 10일 이하)에서 0.053~0.328(명목 0.0025), 실데이터 S3의 58.5%가 노출 1% 미만(root-cause 1-a). S1 이벤트 3개로 t=35 승격(1-b). 시간 단위 공간은 비용 지배(1-c). 심은 알파는 오라클도 검출 불가 강도(1-d).
- 재사용할 코드: `bulk/download.py`·`bulk/extras.py`·`tools/bulk_extras.py`(다운로드·검증·lake 쓰기), `backtest/panel.py:load_panel`(심볼 순차 적재), `data/access.py:PointInTime`(역할별 봉인), `search/pipeline.py:run_family_search`, `strategy/space.py`, `validator/verdict.py`, `validator/null_pipeline.py`, `director/director.py`, `research/guard.py:research_gate`, `adapters/jobhost.py:memory_sample`.

## 근본 원인 (분석 두 건의 종합)
1. **데이터를 안 썼다**(부재가 아님): 81개월·632심볼 중 6개월·8심볼만 연구했다. 그리고 holdout이 4개월이라 판정 자체가 불가능한 설계였다.
2. **검정이 희소 pnl에 취약**하고 **S1이 표본 수를 안 봐서** 노이즈가 위로 올라왔다.
3. **전략 공간이 시간봉·짧은 보유·비용 지배**로 고정돼, 암호화폐에서 문헌상 알려진 일·주 단위 프리미엄(횡단면 모멘텀, 펀딩 캐리, 저변동성 등)을 시험하지 않았다.
4. **파이프라인이 "미통과 = 끝"**이었다. 실패 원인을 다음 실험(데이터·주기·계열)으로 바꾸는 자율 루프가 없었다.

## v2.2 핵심 결정 (A0에서 ADR-040~로 사전 등록, 새 데이터를 읽기 전에)

| D1 | **봉인 epoch 2 = 역사 holdout + 전방 holdout.** 연구 창 = [2020-01-01, 2023-01-01) ∪ [2024-12-01, 2026-07-01). 역사 holdout H_hist = [2023-01-01, 2024-12-01)(23개월, 연구 미접촉 확인됨). 전방 holdout H_fwd = [2026-07-01, 2026-11-01) + 이후 누적. 카탈로그에 `seal_window`(dataset, epoch, role, from, to) 표를 추가하고 `PointInTime`이 창 단위로 거른다(웜업이 holdout에 닿는 결정은 거부). | holdout 23개월이면 α/k 필요 연 SR 4.9 → 2.0. 연구는 55개월로 늘어난다. |

| D5 | **주기·보유 축:** 1h·4h·1d 패널, 리밸런스 주기(1h~7d)·회전율 상한 축, 목표 = 비용 차감 후 성과. vol_target 사전값 유지, 최소 노출 제약 추가. | 1-c. |

## 위험
- **holdout 오염:** LLM이 2023~24 시장을 알 수 있다 → D2(LLM 기원은 H_fwd 필수), 익명화 유지. 역사 holdout이 연구에 새지 않도록 B2를 데이터 확대(B3·B9)보다 먼저 한다.
- **자원:** 16GB 노트북, 가용 3~4GB → 패널 조각 적재·float32·research gate 2GB, 측정은 arm·셀 분할. 수집은 1파일씩, 열 게이트.
- **디스크:** lake 상한 200GB(현재 63GB). tier별 파일럿 투영이 넘으면 그 tier만 멈추고 사용자 결정.
- **시간:** 전체 수집·캠페인은 수일 단위 → 세션 백그라운드 + 예약 작업 스크립트(사용자 등록). 재개 가능성을 테스트로 보장.
- **기준을 바꾸고 싶어지는 유혹:** 결과를 본 뒤 규칙·봉인을 바꾸지 않는다. D1~D3은 A0·B2에서 새 데이터를 읽기 전에 고정하고 해시로 묶는다.
- 알파가 실제로 없을 수 있다. 그 경우 산출물은 "어떤 셀에서 연 SR ≥ X를 검정력 P로 배제했다"는 음성 결과다.
