# 실거래 리허설 절차서 (Phase 7 준비, 설계 v2.1 §11·§16·§17)

> 상태: **코드 준비 완료 / 실행은 사용자 결정 대기.** 이 문서의 어떤 단계도 아직 수행되지 않았다.
> 실거래 거래소 선택과 아래 법률 확인이 끝나기 전에는 테스트넷·형식 검증 단계도 시작하지 않는다.

## 1. 준비된 코드(노트북 쪽)
- `live/signing.py`: ed25519 서명·검증, `SignedPackage`(kind, version 단조, expires), 공개키만으로 검증. `risk/policy.py`가 `Ed25519Verifier`를 그대로 쓴다.
- `live/orders.py`: 거래소별 결정적 client id(Binance ≤36자, Upbit ≤64자), 상태 기계(`UNCERTAIN`은 조회만), 포지션 증가 진입마다 reduce-only 보호 STOP.
- `live/deadman.py`: 하트비트 끊김 시 취소 요청(Binance countdown 계열은 **미확인**, Upbit 일괄 취소 2초 1회), 안전 정지 사유.
- `live/testnet.py`: Binance USDⓈ-M 테스트넷 주문·countdown, Upbit `/v1/orders/test`·일괄 취소의 요청 형식(서명·전송 없음, 경로·파라미터는 리허설 때 공식 문서로 확정, `unverified=True`).
- `risk/limits.py`, `risk/policy.py`: 한도·kill switch·서명 정책(만료·롤백 거부).

## 2. 리허설 순서(각 단계 사이 사용자 승인)
1. **정책 서명 리허설(오프라인):** 오프라인 장치에서 키 생성 → 공개키 32바이트만 실거래 호스트와 저장소 설정에 복사 → 정책 v1 서명 → `PolicyStore.apply`로 검증(변조·다른 키·만료·롤백 거부 테스트는 `tests/live/test_signing.py`).
2. **형식 검증(네트워크, 사용자 실행):** `live/testnet.py`의 요청을 공식 문서와 대조해 `unverified`를 지운 뒤, Upbit `/v1/orders/test`와 Binance 테스트넷에 소량 요청. 응답 코드·필터(최소 명목가, 호가 단위) 기록.
3. **데드맨 리허설:** 실거래 호스트에서 하트비트를 끊고 countdown/일괄 취소가 실제로 미체결을 지우는지 확인(테스트넷).
4. **보호주문 리허설:** 진입과 함께 STOP reduce-only가 들어가고, 하트비트 없이도 거래소 쪽에서 작동하는지 확인(테스트넷).
5. **대사 리허설:** 원장(`paper/ledger.py`와 같은 해시 체인 규약)과 거래소 상태를 대조, 불일치 시 kill이 발동하는지 확인.
6. **휴대폰 수동 청산 절차:** 거래소 앱으로 포지션 전부 청산·주문 취소하는 순서를 문서화하고 1회 연습(테스트넷).
7. **소액 실거래(별도 승인):** 상한 자본·한도 정책 v1·보호주문·데드맨이 모두 켜진 상태로 시작. 30일 모의매매 체결 괴리 보고가 선행 조건(§9-10).

## 3. 이 노트북에서 절대 하지 않는 것
- 거래 키 보관·입력, 개인키 생성, 실주문 전송, 정책 서명.
- `claude` 개발 세션과 같은 계정에서 실거래 프로세스 실행(§11 "같은 관리자 계정은 경계가 아님").
